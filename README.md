# בוט פידבק למסעדות — WhatsApp

בוט רב-מסעדתי (multi-tenant): מספר WhatsApp אחד משרת את כל המסעדות. כל מסעדה
מזוהה לפי `org_id` במסד הנתונים (Supabase), והודעות נכנסות מנותבות אליה אוטומטית.

## איך זה עובד

1. **בעל המסעדה** שולח לבוט צילום מסך של הזמנה (טלפון + שם לקוח).
   הבוט מזהה את הפרטים (Gemini אם מוגדר מפתח, אחרת OCR מקומי) ומתזמן הודעת פידבק.
   התמונה עוברת עיבוד מוקדם לפני הקריאה (תיקון סיבוב לפי EXIF, הגדלה, מתיחת
   ניגודיות, חידוד) ומנוסים כמה רינדורים עד שהפרטים נקראים במלואם.
   אם הקריאה לא ודאית — הבוט מבקש מהבעלים לאשר את המספר לפני שליחה, כדי
   שספרה שנקראה לא נכון לא תשלח הודעה לאדם זר.
2. **אחרי ההשהיה** (מוגדרת פר-מסעדה) הבוט שולח ללקוח את תבנית `order_rating`
   עם חמישה כפתורי דירוג ("היה מדהים" עד "היו לי בעיות בהזמנה").
3. **דירוג 5** → תודה + קישור לדירוג המסעדה בוולט.
   **דירוג 4** → "מה יכול היה להפוך את ההזמנה למושלמת?" — נשמר, בלי התראה למנהל.
   **דירוג 1-3** → רשימת סיבות (האוכל / זמן המשלוח / האריזה / משהו חסר / אחר),
   ומיד עם בחירת הסיבה נשלחת התראה למנהל עם שם, טלפון, מספר הזמנה, סכום,
   דירוג וסיבה. הערה חופשית שהלקוח יכתוב אחר כך נשלחת כהודעת המשך.

> חמש אפשרויות לא נכנסות בכפתורי מענה של WhatsApp (מקסימום 3), ולכן רשימות
> הדירוג והסיבות נשלחות כ-**list message**. אמוג'י אסורים בכפתורי תבנית — ולכן
> כפתורי הדירוג הם מילים, בעוד רשימת הסיבות (הודעת סשן) כן נושאת אמוג'י.

## ניתוב רב-מסעדתי

- הודעה נכנסת ממספר שרשום ב-`org_phones` → זרימת **בעלים** של אותה מסעדה.
- הודעה מלקוח: לחיצת כפתור נושאת `context.id` (מזהה ההודעה המקורית) →
  איתור מדויק של השורה ב-`feedbacks` לפי `wa_message_id`. טקסט חופשי מנותב
  לפי המשוב הפעיל האחרון של אותו מספר.

## מבנה מסד הנתונים (Supabase, פרויקט `restaurant-feedback-bot`)

| טבלה | תפקיד |
|---|---|
| `orgs` | מסעדה: שם, מנהל, קישור וולט, שם תבנית, אימוג'י, השהיה בדקות |
| `org_phones` | טלפונים מורשים לשליחת לקוחות (מפתח הניתוב) |
| `feedbacks` | כל משוב: לקוח, סטטוס, דירוג (1-5), סיבה, מספר/סכום הזמנה, הערה, wamid |
| `org_stats` (view) | סטטיסטיקות לדשבורד |

## דף ניהול

`http://localhost:3000/admin` — כניסה עם `ADMIN_KEY` מה-`.env`.
הוספת/עריכת מסעדות, צפייה במשובים, סטטיסטיקות, שליחה ידנית וביטול.

## הוספת מסעדה חדשה

1. בדף הניהול: "+ הוספת מסעדה" — שם, טלפון מנהל, קישור וולט, טלפונים מורשים.
2. ב-Meta Business Manager: לוודא שיש תבנית הודעה מאושרת עבורה — שם התבנית
   מוגדר פר-מסעדה בדשבורד. `order_rating` מקבלת פרמטר body אחד: שם המסעדה
   והאימוג'י שלה יחד (Meta דוחה משתנים צמודים ודוחה ערך ריק, ולכן זה ערך אחד).

## הרצה

```bash
npm install
npm run build
npm start          # שרת + מתזמן, פורט 3000
npm run test:e2e   # בדיקות קצה-לקצה מול Graph API מדומה (לא שולח הודעות אמיתיות)
```

ה-webhook של Meta צריך להצביע על `https://<domain>/webhook` (בפיתוח: ngrok/cloudflared).

## משתני סביבה (.env)

| משתנה | תיאור |
|---|---|
| `WHATSAPP_TOKEN` | טוקן קבוע (System User) — לא טוקן זמני של 24 שעות! |
| `WHATSAPP_PHONE_NUMBER_ID` | מזהה המספר המשותף |
| `WEBHOOK_VERIFY_TOKEN` | מחרוזת אימות ה-webhook מול Meta |
| `SUPABASE_URL`, `SUPABASE_KEY` | חיבור למסד הנתונים |
| `ADMIN_KEY` | סיסמת דף הניהול |
| `GEMINI_API_KEY` | קריאת שם/טלפון/מספר הזמנה/סכום מתמונות. בלעדיו: ספרות בלבד, בלי שמות. אל תפסול מפתח לפי הקידומת (`AIza` ו-`AQ.` שניהם תקינים) — בדוק מול ה-API |
| `POLL_INTERVAL_MS` | תדירות בדיקת משובים לשליחה (ברירת מחדל 20 שניות) |
